# 02 — Products, editions, modules and the signed documents

## 1. The model (⚑LC3)

```
 Product "yfex-farma"  (declared in code, YFexFarma.Licensing)
 ├── base               = every permission in no module          ── while licensed; product decides what happens without a license
 ├── keep-list          = permissions that never stop             ── history, close the day, export
 ├── Module "fiscal"    = FiscalPermissions.All                   ── + keep-list (view, export XML, transmit pending), meter
 ├── Module "loyalty"   = LoyaltyPermissions.All                  ── + keep-list (view balances)
 ├── Module "delivery"  = DeliveryPermissions.All                 ── + named limit "delivery.integrations"
 └── Module "controlled-medicines" = ControlledMedicinesPermissions.All
 counted roles: Terminal, SiteBroker · scope unit: level 1

 Edition (vendor side only)  "essencial" = fiscal · 2 terminals/store       "completo" = 4 modules · 4 terminals/store · 3 integrations
          │ expanded when the vendor issues
          ▼
 License (vendor-signed)     FarmaViva · yfex-farma · modules [fiscal, loyalty, delivery, controlled-medicines] · seats · limits · dates
```

A **module is a set of permissions**, because permissions are already what every gate, menu, search and AI tool checks
([06](06-feature-gating.md)). There is no second "feature flag" vocabulary for developers to learn.

| Rule | Why |
|---|---|
| A permission belongs to **at most one** module (checked when the product is built; `LicensingConfigurationException` names both) | a permission in two modules makes "is it available?" depend on the order of modules |
| A permission in no module is **base** | most permissions are base; nothing to declare for them |
| Module ids, limit ids and meter ids are **explicit strings**, never derived from type names | they are stored in licenses signed for years; a rename in code must not change them |
| `KeepWhenUnavailable` permissions must belong to the module (or to base for the product-level list) | the keep-list is the module's own "read-only face" |
| Ids use lowercase `a-z0-9.-`, ≤ 64 characters | they appear in canonical bytes, URLs and denial codes |

## 2. Catalog types (YFex.Licensing, normative)

```csharp
namespace YFex.Licensing;

public readonly record struct ProductId(string Value);       // "yfex-farma"
public readonly record struct ModuleId(string Value);        // "fiscal"
public readonly record struct LimitId(string Value);         // "delivery.integrations"
public readonly record struct MeterId(string Value);         // "fiscal.documents-issued"

public enum UnlicensedBehavior : byte
{
    BaseOnly = 1,    // without a valid license: base + keep-lists work (a product with a free core)
    ReadOnly = 2,    // without a valid license: only the keep-lists work (a paid core: YFex Farma)
}

public sealed class LicensedProduct                          // immutable after Define; one per product
{
    public static LicensedProduct Define(ProductId id, Action<ProductBuilder> configure);
    public ProductId Id { get; }
    public string DisplayName { get; }
    public ImmutableArray<InstallationRole> CountedRoles { get; }
    public int ScopeUnitLevel { get; }
    public TimeSpan BaseContinuesAfterExpiry { get; }
    public UnlicensedBehavior WithoutLicense { get; }
    public ImmutableArray<LicensedModule> Modules { get; }
    public CatalogManifest Manifest { get; }                 // ids + permission ids + limits + meters, canonical JSON for the snapshot test

    public ModuleId? ModuleOf(Permission permission);        // null = base
}

public sealed record LicensedModule(ModuleId Id, PermissionSet Grants, PermissionSet KeepWhenUnavailable,
    ImmutableArray<LimitId> Limits, ImmutableArray<MeterId> Meters);

public sealed class ProductBuilder
{
    public ProductBuilder DisplayName(string name);
    public ProductBuilder CountSeats(params ReadOnlySpan<InstallationRole> roles);         // default Terminal + SiteBroker
    public ProductBuilder ScopeUnit(int level);                                            // default 1
    public ProductBuilder KeepWhenUnavailable(params ReadOnlySpan<Permission> permissions);// product level (base keep-list)
    public ProductBuilder BaseContinuesAfterExpiry(TimeSpan period);                       // default 30 days
    public ProductBuilder WithoutLicense(UnlicensedBehavior behavior);                     // default ReadOnly
    public ProductBuilder Module(ModuleId id, Action<ModuleBuilder> configure);
}

public sealed class ModuleBuilder
{
    public ModuleBuilder Grants(IEnumerable<Permission> permissions);                      // FiscalPermissions.All (generated by Authorization)
    public ModuleBuilder Grants(params ReadOnlySpan<Permission> permissions);
    public ModuleBuilder KeepWhenUnavailable(params ReadOnlySpan<Permission> permissions);
    public ModuleBuilder Limit(LimitId limit);
    public ModuleBuilder Meter(MeterId meter);
}
```

`Permission` and `PermissionSet` are YFex.Authorization.Public types. `Define` builds the module masks once as `PermissionSet` bitsets,
so gating costs one bitset intersection per license change, not per check (06 §3).

### 2.1 The catalog manifest snapshot

`LicensedProduct.Manifest.ToJson()` produces a stable, sorted document:

```json
{ "product": "yfex-farma", "scopeUnitLevel": 1, "countedRoles": ["Terminal", "SiteBroker"],
  "withoutLicense": "ReadOnly", "baseContinuesAfterExpiryDays": 30,
  "keep": ["reports.export", "sales.close-day", "sales.view-history"],
  "modules": [
    { "id": "delivery", "permissions": ["delivery.configure", "delivery.dispatch", "delivery.view"], "keep": [], "limits": ["delivery.integrations"], "meters": [] },
    { "id": "fiscal", "permissions": ["fiscal.cancel", "fiscal.issue", …], "keep": ["fiscal.export-xml", "fiscal.transmit-pending", "fiscal.view-documents"], "limits": [], "meters": ["fiscal.documents-issued"] } ] }
```

- The **app** solution has a test `LicensingCatalogSnapshot.Verify(YFexFarmaLicensing.Product, "licensing-catalog.json")` that fails
  when the committed file differs, so moving a permission between modules shows up in review.
- The **vendor service** loads the same product from the shared assembly and refuses an edition naming a module that does not exist.
- Licenses carry the manifest's `Hash256` (`CatalogHash`) of the version they were issued against, **for diagnostics only**: an
  installation running an older or newer app version still evaluates the license (unknown modules are ignored, modules the license
  does not list are unavailable).

## 3. Editions are vendor templates (⚑LC3)

```csharp
// YFex.Licensing.Vendor — only the vendor's service knows editions
public sealed class EditionBuilder
{
    public EditionBuilder Modules(params ReadOnlySpan<ModuleId> modules);
    public EditionBuilder Seats(InstallationRole role, int? perScope = null, int? total = null);
    public EditionBuilder Limit(LimitId limit, long value);
    public EditionBuilder Trial(TimeSpan length);             // default trial shape for this edition (03 §5)
}
```

- Issuing a license **copies** the edition's modules, seats and limits into the License; the issuer may override any of them
  (FarmaViva got `Total: 120` terminals). The License stores `Edition = "completo"` **as text for display only**.
- Changing what "completo" means affects **new** licenses and renewals, never a signed one. To give FarmaViva a new module the
  vendor issues a new License with a higher `Sequence` (minutes; it reaches the shops at the next push or check-in).
- **Add-ons**: a module may carry its own period (`ModuleGrant.Period`) — "delivery for 3 months as a promotion" — without touching the
  subscription.

## 4. Several products per tenant (⚑LC22)

A License is for one **(tenant, product)**. FarmaViva might buy YFex Farma and, separately, a delivery-courier mobile app
(`yfex-farma-entregas`). Each app registers its product(s) with `.Product(...)`; central keeps one License stream per product;
seats are counted per product (the courier app's installations are not checkout seats). Installations of one product ignore the
other product's bundles (wrong stream).

## 5. The signed documents (⚑LC2, ⚑LC5)

Both are **payloads of Installations' `SignedBundle`** (installations 05 §3) with publisher `vendor` (⚑I23): the header, floors,
gossip and storage are Installations'; licensing only defines the payloads and how to read them. Canonical binary through
YFex.Cryptography's `CanonicalWriter` (shown as records).

```csharp
namespace YFex.Licensing;

public readonly record struct LicenseId(Guid Value);          // Guid v7 minted by the vendor; ICanonicalValue (16 bytes)

public enum LicenseKind : byte { Commercial = 1, Trial = 2 }
public enum LicenseHosting : byte { VendorHosted = 1, CustomerHosted = 2, Disconnected = 3 }   // ⚑LC19, closed set

public sealed record License(
    LicenseId Id,
    long Sequence,                                  // = BundleHeader.Version of the stream; a new issue is always higher
    string Customer,                                // vendor's account id ("farmaviva"), display + check-in
    string Tenant,                                  // scope level-0 text; must equal the installation's tenant
    Hash256 TenantRoot,                             // SHA-256 of the tenant root CA SubjectPublicKeyInfo, learned at activation
    ProductId Product,
    string Edition,                                 // display only
    LicenseKind Kind,
    LicenseHosting Hosting,
    ValidityPeriod Subscription,
    LicenseTimings Timings,
    ImmutableArray<ModuleGrant> Modules,
    ImmutableArray<SeatLimit> Seats,
    ScopeLimit? Scopes,
    ImmutableArray<LimitGrant> Limits,
    bool MeteringEnabled,                           // ⚑LC15
    Hash256 CatalogHash);                           // diagnostics only (§2.1)

public sealed record LicenseTimings(
    TimeSpan SubscriptionGrace,                     // default 15 days (⚑LC11)
    TimeSpan OfflineAllowance,                      // SaaS 30 days, on-premises 45, disconnected 180 (⚑LC12)
    TimeSpan CheckInInterval,                       // on-premises 1 day, disconnected 90 days; SaaS: not used
    TimeSpan ActivationGrace);                      // default 7 days (⚑LC7)

public sealed record ModuleGrant(ModuleId Module, ValidityPeriod? Period);            // null = the subscription period
public sealed record SeatLimit(InstallationRole Role, int? PerScope, int? Total);      // null = unlimited on that axis
public sealed record ScopeLimit(int Level, int Count);                                // "40 scopes at level 1"
public sealed record LimitGrant(LimitId Limit, long Value);

public sealed record ActivationList(
    LicenseId License,
    string Scope,                                   // "0=farmaviva/1=loja-centro" (the scope unit)
    long Version,                                   // = BundleHeader.Version of the stream
    ImmutableArray<Activation> Activations,
    ImmutableArray<ActivationRefused> Refused);     // installations the vendor saw and refused (03 §3), shown during their grace

public sealed record Activation(InstallationId Installation, InstallationRole Role, KeyId EvidenceKey, DateTimeOffset ActivatedAt);
public sealed record ActivationRefused(InstallationId Installation, SeatRefusal Reason);
```

| Bundle kind | Stream | Audience (`BundleAudience`) | `ValidUntil` in the header | Size (FarmaViva) |
|---|---|---|---|---|
| `licensing.entitlements` | product id (`yfex-farma`) | `Tenant` = `farmaviva` | subscription end + grace + base continuation (the document's meaning ends there) | ≈ 1 KB |
| `licensing.activations` | scope unit text | `Scope` = that scope | same as the License it cites | ≈ 40 bytes × activations (Loja Centro: 5 → 0.3 KB) |
| `licensing.vendor-keys` | `vendor` | `Tenant` (every tenant gets the same signed list) | none (superseded by version) | < 0.5 KB |

Installations above the scope unit (the regional laptop at `0=farmaviva/1=regiao-sul`, level 1 too in FarmaViva's tree) get the list
of **their own** scope. A tenant whose machines sit at level 0 (a single-store customer without a store level) gets one list with
stream = the tenant scope.

**Why freshness is not in the bundle header:** if `ValidUntil` were "issued + 45 days", Installations' verifier would refuse an old
License as `Expired` and the installation would fall to "no license" at once. Licensing instead keeps the document and evaluates its
age itself (`IssuedAt` + `OfflineAllowance` → `LicenseGraceReason.OfflineTooLong`, [04](04-validity-expiry-grace-offline.md) §4), so a
store that loses contact gets the grace and the warnings first.

**Verification order on every installation** (at receipt and at every load, like every bundle):

1. Installations' `IBundleVerifier` with the **vendor** publisher: signature by a pinned or key-list vendor key, audience, floor,
   same-version conflict → anything but `Valid` is dropped and the last good document stays in effect.
2. Licensing: `Tenant` equals `LocalInstallation.Current.Scope`'s level 0; `TenantRoot` equals the hash of the installation's pinned
   tenant root; `Product` is registered → otherwise `LicenseRejection.WrongTenant/WrongTenantRoot/WrongProduct` (a finding).
3. Activation lists: `License` equals the current License id (a list for an old license is kept but not used).
