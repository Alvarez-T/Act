# 13 — Performance, AOT, platforms and generators

## 1. Hot paths and budgets (measured in BenchmarkDotNet before each phase closes)

| Path | Frequency | Budget | How |
|---|---|---|---|
| access-token validation, cache hit | every HTTP request / RPC call with a header token | **< 150 ns, 0 B** | span hash probe, `SequenceEqual`, revoked-set lookup (07 §5) |
| access-token validation, cache miss | once per token per node | **< 120 µs**, allocations = the cached caller only | stack-decoded JSON, cached `SignatureVerifier` per `kid`; ECDSA P-256 verify dominates |
| `AssuranceLevel` from a method set; `RequireRecentAuthentication` check | per gated command | **< 10 ns, 0 B** | bitset + two claim reads cached on `AuthenticatedCaller` |
| throttle `Check` (in-memory) | per sign-in/code attempt | **< 100 ns, 0 B** | fixed counters, no LINQ |
| code check | per attempt | **< 2 µs** + store | one HMAC into a stack buffer, `FixedTimeEquals` |
| token issue | per sign-in/refresh | **< 200 µs** | `Utf8JsonWriter` over pooled buffer, ES256 sign |
| password verify | per password sign-in | **PBKDF2 600 000 ≈ 150–250 ms** (CPU-bound by design) | concurrency limiter so a burst cannot starve the API (04 §2) |

Rules applied everywhere: no LINQ and no `params` arrays on these paths; no `string.Split`/`Substring` (spans); claim names as
`"…"u8` literals; `[Union]` results (`TokenValidation`, `ThrottleDecision`, `ChallengeCheck`, `ReauthenticationResult`) read with
`TryGetValue`, never `.Value`; buffers from `stackalloc` (≤ 1 KB) or `ArrayPool<byte>.Shared` and zeroed when they held secrets.
`unsafe` is **not** needed for the measured cases: `[InlineArray]` fixed buffers (`VerificationCode`) and `MemoryMarshal` cover them;
revisit only if a benchmark shows bounds checks matter (they should not next to a signature verification).

## 2. AOT and trimming

- `IsAotCompatible`, `<PublishAot>` smoke (`YFex.Authentication.AotSmoke`) with **0 warnings** for: engine, `.OpenIdConnect`,
  `.AspNetCore` (minimal APIs with the request-delegate generator), `.Delivery`, `.Client`, `.Rpc`.
- JSON: one `JsonSerializerContext` per package (`AuthenticationJsonContext`, `OpenIdConnectJsonContext` for discovery, JWKS and token
  responses, `DeliveryJsonContext` for Twilio/Meta payloads). JWT headers/payloads use `Utf8JsonReader/Writer` directly.
- No `Microsoft.IdentityModel.*` and no `Microsoft.AspNetCore.Authentication.JwtBearer/OpenIdConnect` in our packages (⚑AN10);
  apps that keep "bring your own IdP" still use Authorization's `AddYFexAuthorizationJwtBearer`.
- No reflection-based options binding on hot paths; configuration through builders (like `AddYFexAuthorization`).
- Value objects: `TypeConverter` + STJ converters registered explicitly (no `[JsonConverter]` reflection activation issues under
  trimming — follow Authorization's value objects, which are already AOT-tested).

## 3. Data shipped with the library

- **Common-password list**: top 100 000 passwords → normalised (NFC, lower-case) → 64-bit `StableHash64` (core) → sorted
  `ulong[]` embedded as a resource (~800 KB); loaded lazily into a `ReadOnlySpan<ulong>` view, binary search per check (≈ 17
  comparisons). A false positive (64-bit collision) only refuses one extra password. Regenerated by a script in the repo
  (`tools/build-common-passwords`), not at build time.
- Default message templates (pt-BR, en, es) as embedded UTF-8 resources parsed once.

## 4. Platforms (yfex-cross-platform)

| Concern | Windows | Linux | macOS | Notes |
|---|---|---|---|---|
| server engine | ✓ BCL | ✓ BCL | ✓ BCL | no OS code |
| PBKDF2 / HMAC / ECDSA / RSA verify | CNG | OpenSSL | Apple CryptoKit/Security via BCL | through YFex.Cryptography |
| desktop token storage | CNG/TPM root key | file root key 0600 (crypto 14) | Keychain spike or file root key | through YFex.Cryptography + Persistence; **no `.Windows/.MacOS/.Linux` package here** |
| system browser launch | `Process.Start(UseShellExecute = true)` | `xdg-open` via the same BCL call | `open` via the same BCL call | verify on each OS in the P4 spike |
| loopback redirect listener | `HttpListener` on `127.0.0.1` (no URL ACL needed for loopback) | `HttpListener` (managed) | `HttpListener` (managed) | spike: confirm the managed listener on Linux/macOS binds `127.0.0.1:0`; fallback a minimal `Socket`-based one-request listener |
| SMTP | BCL `SmtpClient` | same | same | |
| `NormalizationForm.FormC` | ✓ | ✓ unless `InvariantGlobalization=true` | ✓ | `PasswordHashing` already detects missing normalisation (crypto gotcha); servers must not run with invariant globalization, or passwords with accents fail across keyboards — the AotSmoke checks it |

## 5. Source generators — where they would help, and the decision (⚑AN21)

| Candidate | Would generate | Verdict |
|---|---|---|
| JSON wire types (discovery, JWKS, token responses, endpoints, Twilio/Meta) | serializers | **use the BCL STJ generator** (no custom code) |
| endpoint registration (`MapYFexAuthentication`) | request delegates | **ASP.NET's request-delegate generator** already makes minimal APIs AOT-safe |
| `AuthenticationPermissions` catalog | ids, manifest, registration | **existing Authorization generator** |
| classified value objects (`EmailAddress`, `PhoneNumber`, `VerificationCode`, `Password`) | masks, log writers | **existing Privacy + Logging generators** |
| provider descriptors / claims mapping | mapping code | **no** — five small hand-written mappers, each with provider-specific security rules that must be read by a reviewer |
| app-declared methods/channels/purposes (`AuthenticationMethod.Declare("…")`) | interned statics | **no** — a `static readonly` field per value, the same way `DataCategory.Define` works; no attribute per member (api-naming rule) |
| message templates checked at compile time | template plans | **not now**: templates are per-scope runtime data (tenant branding). Reconsider if compile-time default templates show up in profiles |
| account profile extensions | partial records | **no** — the app keeps its own table keyed by `AccountId` (model-layering) |

Result: **no new generator project**. Every syntax simplification needed is achieved with builders, value objects and the existing
generators.
