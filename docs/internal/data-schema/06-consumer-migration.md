# 06 — Consumer migration

Each consumer swaps `Statements(SqlEngine)` for a `SchemaModule`, deletes its engine enum, registers the module, and adds
one validation test across every dialect. The stores themselves do not change in DS-P3. DML clean-ups are DS-P6. Row classes generated by DS-P4 are optional for these libraries (⚑DS11).

## 1. YFex.Offline.Data

Before (`OfflineSqlSchema.cs`): `enum SqlEngine` + `Statements(SqlEngine)` with 7 type variables.

After:

```csharp
// (sketch)
namespace YFex.Offline.Data;

/// <summary>The tables of Offline's central stores (offline 11 Phase 3e). Apply with ApplySchemaAsync or script with ScriptSchema.</summary>
public static class OfflineSqlSchema
{
    // Portable conventions of this module (documented once, not per engine):
    static ColumnType Id => ColumnType.AsciiString(36);     // GUID text
    static ColumnType Key => ColumnType.String(450);        // indexable text (SQL Server key limit)
    static ColumnType Text => ColumnType.String(400);
    static ColumnType LongText => ColumnType.String();
    static ColumnType Instant => ColumnType.Int64;          // Unix ms
    static ColumnType Small => ColumnType.Int16;
    static ColumnType Bytes => ColumnType.Binary();

    public static TableSchema Receipts { get; } = TableSchema.Create("offline_receipts", t => t
        .Column("idempotency_key", Id).PrimaryKey()
        .Column("outcome", Small).Column("error_kind", Small)
        .Column("detail", LongText, nullable: true)
        .Column("findings", ColumnType.Int64).Column("processed_at", Instant)
        .Index("ix_offline_receipts_processed", "processed_at"));
    // … Sessions, Sequences, Claims, Spending, ReviewItems, Findings, Parked, SiteSettings, Publications, Deliveries, Idempotency

    public static SchemaModule Module { get; } = new SchemaModule("yfex.offline")
        .Version(1, "Central stores (offline 11 Phase 3e)", v => v
            .CreateTable(Receipts).CreateTable(Sessions) /* … */ .CreateTable(Idempotency));
}
```

- `AddYFexOfflineData` registers `OfflineSqlSchema.Module` into `SchemaRegistry`, and its doc comment changes from
  "Create the tables with `Statements`" to "apply with `ApplySchemaAsync` / `ScriptSchema`, or `ApplyOnStartup`".
- Tests (`DataTests`): `connection.ApplySchemaAsync([OfflineSqlSchema.Module])` on SQLite replaces the `foreach`
  over `Statements(SqlEngine.Sqlite)`. The engine-type assertions (`varbinary(max)`, `bytea`) move to YFex.Data's golden
  tests, and Offline keeps `SchemaAssert.Valid(OfflineSqlSchema.Module, <all four dialects>)`.
- AOT smoke and benchmark: `ScriptSchema(PostgresDialect.Instance, …)` / `ApplySchemaAsync` instead of `Statements`.
- Optional, once the module exists: stores that want bulk paths take `OfflineSqlSchema.Receipts.ToBulkTable()`
  instead of a hand-written column list.

**Validation findings expected on day one** (they exist today; nothing reports them):

- **SQL Server, YFSCH003: four primary keys are wider than the 900-byte clustered-key limit.** `offline_claims`
  (`nvarchar(450)` × 2 = 1,800 bytes), `offline_spending` (≈1,844), `offline_publications` (≈1,708), and
  `offline_deliveries` (≈1,752). SQL Server creates them with a warning only, then rejects any insert whose actual key
  exceeds 900 bytes. Fix in version 1, since nothing is deployed: shorter `Key`/`Text` lengths for key columns (e.g.
  `String(200)`), or `nonclustered` primary keys (1,700-byte limit), either through a `PrimaryKeySchema` option the SQL
  Server generator honours or through a narrower model. Decide when implementing DS-P3.
- Oracle < 12.2 only (30 characters), YFSCH001: `ix_offline_idempotency_completed` (32).
- Not a schema item but a store review item before claiming Oracle: **Oracle stores `""` as NULL**, so writing an empty
  string into a `NOT NULL` text column fails. Types are otherwise fine: every key column is bounded.

## 2. YFex.Authentication.Data

Same pattern; module `yfex.authentication`. Notable lines:

```csharp
// (sketch)
// today: engine == SqlServer ? "create unique index … where operator_code is not null" : "create unique index …"
.Column("operator_code", ColumnType.String(12), nullable: true)
.UniqueIndex("ux_authentication_operator_codes", "realm", "operator_code")    // NULL never collides: every dialect honours it (03 §4)

// today: key = bytea / varbinary(64) / blob
.Column("lookup_key", ColumnType.Binary(64))

// today: name = varchar(32) / text
.Column("provider", ColumnType.AsciiString(32))

// ⚑DS9: descriptor stays opaque text
.Column("descriptor", ColumnType.String())
```

Identifier check for Oracle < 12.2 / 30 characters: `ix_authentication_external_logins_account` (41),
`ix_authentication_challenges_destination` (40), `ux_authentication_contacts_lookup` (33) and others exceed 30. They
are fine on Oracle ≥ 12.2 (128) and PostgreSQL (63). YFSCH001 uses the dialect's configured limit
(`OracleDialect` option `LegacyIdentifierLength`, default off).

## 3. YFex.Rules.Data (`YFex/src/Validation`)

`SqlRuleStore.CreateTableScript(RuleStoreDatabase, table)` takes the table name as a parameter. That means the module
is built per table name: `RuleStoreSchema.Module(string table = "yfex_rule_data")` returns a `SchemaModule` named
`yfex.rules:{table}`. `RuleStoreDatabase` is removed. Rules.Data already supports Oracle by hand (`VARCHAR2(n CHAR)`,
`NUMBER(5)`), so its golden output is a good cross-check for the Oracle generator.

## 4. YFex.Security (later, with its deferred move to YFex.Data, Q8)

`MigrationRunner` + `_migrations` (SQLite, Dapper) becomes a `SchemaModule` (`yfex.security`) whose versions are its
existing migrations. Any SQLite-only SQL in them becomes a `SqlStep.For(ProviderId.Sqlite, …)`. Its existing
`_migrations` rows map to `yfex_schema_history` once, via a version-0 adoption step: "if `_migrations` says N, record
1…N as applied". Do this only when YFex.Security moves to YFex.Data.

## 5. Breaking changes and order

| Repo | Breaks | Who is affected |
|---|---|---|
| YFex.Data | `ITable` & co. removed | `DataAccessTests` only |
| YFex.Offline | `SqlEngine`, `OfflineSqlSchema.Statements` removed | its tests, AOT smoke, benchmark |
| YFex.Authentication | `SqlEngine`, `AuthenticationSqlSchema.Statements` removed | its tests, AOT smoke |
| YFex (Rules.Data) | `RuleStoreDatabase`, `CreateTableScript` removed | its tests |

No shim (`[Obsolete] Statements(SqlEngine)`): no host calls these methods today, and a shim would keep the second
selector alive. If the user prefers one release of overlap, `Statements(SqlEngine e)` can become
`ScriptSchema(DialectFor(e), Module)` for that release.
